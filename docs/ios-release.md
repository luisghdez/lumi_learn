# iOS Release Guide

## Every Release Checklist

### 1. Update version in `pubspec.yaml`

```yaml
version: MAJOR.MINOR.PATCH+BUILD_NUMBER
```

- **Version** (`MAJOR.MINOR.PATCH`): increment when you have new features or fixes
- **Build number**: always increment by 1 from the last App Store upload — never reuse or go backwards

Example:
```yaml
version: 2.1.0+11
```

---

### 2. Sync `ios/Runner.xcodeproj/project.pbxproj`

These fields are hardcoded in the Xcode project and take precedence over `Generated.xcconfig`.
They appear **3 times each** (Debug, Profile, Release) and must all match `pubspec.yaml`.

| Field | Example value |
|---|---|
| `FLUTTER_BUILD_NAME` | `2.1.0` |
| `FLUTTER_BUILD_NUMBER` | `11` |
| `CURRENT_PROJECT_VERSION` | `11` |
| `MARKETING_VERSION` | `2.1.0` |

Use find & replace all in the file to update each one.

> **Note:** `Generated.xcconfig` is auto-generated by `flutter pub get` and should never be
> edited manually. However, the hardcoded pbxproj values override it, so both must be kept in sync.

---

### 3. Build the IPA

```bash
cd /path/to/lumi_learn
flutter build ipa
```

> **Important:** Use `flutter build ipa` instead of Xcode's **Product → Archive**.
> Xcode Archive fails with "Module not found" errors because it builds in a clean environment
> where pod frameworks aren't compiled in the right order. Flutter's build command handles
> this sequencing correctly.

---

### 4. Open the archive in Xcode Organizer

```bash
open build/ios/archive/Runner.xcarchive
```

Then in Organizer: **Distribute App → App Store Connect → Upload**

This is equivalent to the normal Xcode Archive → Distribute flow.

---

## Troubleshooting

### "Module 'audioplayers_darwin' not found" during Xcode Archive

This is a known build-order issue with `use_frameworks!` in Flutter projects.
**Fix:** Use `flutter build ipa` as described above instead of Xcode Archive.

### Build number rejected by App Store Connect

App Store Connect requires the build number to be strictly greater than all previously
uploaded builds for the same version. If a submission is rejected or cancelled, you still
need to increment the build number for the next attempt.
